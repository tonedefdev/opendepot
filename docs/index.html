    What OpenDepot serves¶

    OpenDepot is an open source artifact registry that runs in your Kubernetes cluster. It serves:

    • Agent Skills and Agents published from Git repositories and installed with the opendepot CLI.
      • Signed when published and checked before install. Agent hooks run opendepot verify before each tool call and block the call until an edited skill or agent is restored. See verifying with agent hooks.
    • Modules and providers for OpenTofu and Terraform, through the registry protocol.

    MCP servers and OCI artifacts are planned. Registry clients read through the server. Kubernetes RBAC governs changes to artifacts. The server's only Kubernetes write path is ScanPolicy, which is off by default.

    Where to start¶

    •  Install

      Deploy with the Helm chart, or run a local registry with kind. Start with the Modules and Providers quickstart or the Agents and Skills quickstart. See installation.

    •  Publish Skills and Agents

      Publish Skills and Agents from Git tags or branches, either as standalone resources or through a Depot. See publishing Agents and Skills.

    •  Consume Skills and Agents

      Install versioned Skills and Agents with the opendepot CLI, which verifies signed checksums before use. See consuming Agents and Skills.

    •  Publish modules and providers

      Create a Depot that polls your module and provider sources, or manage them declaratively with GitOps. See the Depot workflow.

    •  Consume modules and providers

      Point OpenTofu or Terraform at the registry. See consuming modules and consuming providers, or compose them into a validated root module with the Assembly Line.

    •  Browse and secure

      Browse artifacts in the OpenDepot Workshop, manage Security Policies, and review vulnerability scanning.

    For how the system fits together, see Architecture. For deployment options, see Configuration. For API and CLI details, see Reference.
