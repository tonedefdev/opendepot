Announcing agents and skills

Something rewrote your skill. OpenDepot blocked it.

OpenDepot is the self-hosted registry for OpenTofu and Terraform modules and providers, and it now ships agents and skills as signed Versions. The opendepot CLI pins them in a lock file. Before each tool call, a hook checks installed files against that lock and blocks the call if they don't match, even when a prompt says otherwise. Commit the lock file, and every change to it shows up in review.

Branch mode

Push to a branch. Jev picks the release.

Point a source at a branch instead of tags. Every commit that passes the checks becomes a Version, and Jev reads the change to decide whether it ships as a patch, minor, or major release.

  • Your thresholdsmajorThreshold and minorThreshold turn Jev's probabilities into a semver bump.
  • Pinned commitsEach Version records its exact commit. Pushes inside minVersionInterval collapse into one Version.
  • People stay in chargeLow confidence flags a bump for review, and an annotation can override it.

Off by default. Enable it with branchSourcing.enabled in the Helm chart. Without Jev, every commit is a patch.

Jev is off by default and opt-in per source. When enabled, skill and agent text is sent to TypeSafe for assessment. OpenDepot is not affiliated with TypeSafe. Read the agents guide

The opendepot CLI

Plan your agents. Apply when you're ready.

The opendepot CLI works like tofu for skills and agents. Declare what a project needs, review the plan, and apply only when it looks right. Every package is checked against its GPG signature and pinned in a lock file.

  1. 01Declare

    Choose install targets and version constraints.

    opendepot.hcl
    opendepot {
  targets = ["copilot", "claude"]
}

agent_skill "release-notes" {
  source  = "registry.acme.io/ai/release-notes"
  version = "~> 1.2"
}

agent "code-reviewer" {
  source  = "registry.acme.io/ai/code-reviewer"
  version = ">= 2.0.0, < 3.0.0"
}
  2. 02Plan

    See every add, change, and overwrite. Nothing is written.

  3. 03Apply

    Verify the GPG signature and hashes, install, and pin the signing key in the lock file. opendepot verify catches drift in CI.

    opendepot.lock.hclGPG verified
    agent_skill "registry.acme.io/ai/release-notes" {
  version        = "1.3.1"
  constraints    = "~> 1.2"
  signing_key    = "F293651BA42FE9E0C32C8283E17CC7D19FF4697D"
  signature_hash = "sha256:17c924be8f2f95a638cfd539a780…"
  hashes         = ["h1:THQgwxu+vlYPt82Bfz3T…", "zh:a8e5e75a…"]

  installed "copilot" {
    path = "/Users/you/.copilot/skills/release-notes"
    hash = "h1:THQgwxu+vlYPt82Bfz3T…"
  }
}
  4. 04Resolve

    The highest matching Version wins. Yanked and Jev-blocked Versions are skipped, and the lock holds your version until apply --upgrade.

Verify with agent hooks

Every tool call answers to the lock file.

A tool hook runs opendepot verify before each tool call an agent makes. When an installed skill or agent no longer matches opendepot.lock.hcl, the hook denies the call and tells the agent to restore the locked version with opendepot apply.

01At every tool call

The call runs only when the installed files match the lock. While they differ, the hook lets through two exact commands and nothing else.

02When a version should change

The hook checks installed files, not your config. Commit opendepot.hcl and opendepot.lock.hcl, and a new version arrives as a diff for someone to approve.

What still takes a person

  • A new signing keyapply pins the signer on first install. A rotated key is trusted only when you confirm it or pass --trust-new-key. With --no-prompt, it fails instead of asking.
  • A hand-edited AGENTS.md blockapply refuses to overwrite it and the hook blocks apply --force. The agent stops and tells you.
  • A failed restoreIf the registry is unreachable or credentials are missing, the hook keeps blocking and the agent reports the failure.
  • The hook itselfProject hook config lives in the repository, where an agent could remove it. Deploy it as a managed hook to prevent that.

The hook is the enforcement layer. The CLI does not block edits by itself, and a hook runs before a tool call, so an edit still lands on disk and the next call is the one denied. Read the hooks guide

Jev confidence scores

Read the risk before it ships. Scores, not verdicts.

When Jev is enabled on a source, each skill and agent Version is scored for prompt injection, exfiltration, destructive actions, hidden instructions, and scope mismatch. You get probabilities with a confidence value, and your policy decides what gets blocked.

  • Probabilities, not verdictsEach score is a model estimate. It is not a certification or an OpenDepot verdict.
  • Your policy decidesjevPolicy thresholds block a Version. Low confidence only marks it for review.
  • Confidence sits beside riskA Low risk level at 32% confidence reads differently from the same level at 90%.

In our synthetic held-out test, Jev blocked all 60 malicious skills. SkillSpector's static scan rated 15 of those 60 SAFE. Four attack families. Jev jev-1.14.0 with the OpenDepot gate. SkillSpector 2.12.0, static scan only. One run per arm.

Read the agents guide for thresholds, exemptions, and how Jev assesses large Versions.

Versioning

Constraints you can read. Versions you can verify.

Constraints choose which tags become Versions. Every Version is packaged, signed, and checked, and yanked or blocked Versions are handled explicitly.

  • Constraints for tags

    Git tags that match the constraint become Versions. Branch sources set ref instead.

    versionConstraints: "~> 0.9.0"

  • Signed on every Version

    Each archive gets a SHA256SUMS file signed with your GPG key. The agents.v1 API serves the checksums and signature next to the archive.

  • Yanked, still downloadable

    Set spec.yanked: true to retire a Version. It stays downloadable, and the CLI skips it unless you pass --allow-yanked.

  • Blocked, never served

    A Version that a Jev policy blocks is listed with its reasons. A direct download returns 404.

Fine-grained scan policy

Waive one finding. Keep every other gate.

Global thresholds block everything or nothing. ScanPolicy sets severity and exact, expiring exemptions per namespace, module, provider, or version range, and the Registry Explorer lets the right people manage them.

  1. 01
    Target precisely

    Pin a policy to named Modules or Providers and a version constraint, or cover a group with a label selector.

  2. 02
    Highest priority wins

    Policies never merge. The winner applies in full, and every other match reports who superseded it.

  3. 03
    Exemptions expire

    Exempted findings stay visible on the Version. When an exemption expires, blocking resumes on its own.

  4. 04
    Scoped administration

    SecurityGroupBindings map OIDC groups to namespaces and resources. The server re-authorizes every preview, save, and delete, and fails closed.

Assembly Line

Compose root modules from parts you already trust.

Wire module outputs to inputs on a visual canvas built from your onboarded, scanned versions. OpenDepot validates the result against your own registry and hands back clean OpenTofu.

  1. 01Select

    Modules and OpenTofu providers pinned to exact versions with extracted contracts.

  2. 02Wire

    Connect variables and outputs to inputs, alias providers, and repeat modules with count or for_each.

  3. 03Validate

    The server re-authorizes every node and runs tofu init through OpenDepot's provider mirror. No public fallback.

  4. 04Export

    Download main.tf and variables.tf. No state, lock files, or credentials.
